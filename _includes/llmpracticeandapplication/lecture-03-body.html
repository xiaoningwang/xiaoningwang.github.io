一、如果老师不再替你选材料

上一讲的活动咨询题给了两份材料。我们可以从“限额 80 人”和“本科生 42 人、研究生 18 人已确认”算出还有 20 个名额。这个答案有两个前提：两类名单已经去重，数字对应同一场活动。至于“报名收费吗”，材料没有写，回答“免费”就超出了证据。

现在把两份材料换成一个资料夹，里面有海报、旧版须知、补充通知和几场名称相似的活动。提问者只输入一句话。即使沿用上一讲最好的提示，系统仍要先解决三个问题：到哪里找，取哪一段，凭什么把这一段用在眼前这个问题上？ 这就是本讲从提示设计转向检索增强生成的起点。

本讲结束时，请拿自己的一个回答做演示：点出其中一项可核查的事实，找到本次检索返回的原句，再说明这句话的日期、对象和适用条件。如果同伴发现一句话回不到材料，能够指出证据在哪一步丢失，就已经找到了值得修改的地方。

二、把一次问答拆成两条路径

检索增强生成（Retrieval-Augmented Generation，RAG）让系统按问题从外部资料中选取片段，再把选中的内容交给生成模型。Lewis 等人的原始研究把神经检索器和生成模型组成可训练的系统。课堂上采用容易拆开检查的做法：先冻结一个小资料库，把检索结果保存下来，再据此组织答案。更新通知时可替换资料、重建受影响的索引，并复测相关问题。Lewis 等，2020

路径 操作顺序 留给同伴核查的记录
建库时 选取有权使用的原件 → 提取正文 → 按条款或段落切分 → 建索引 原件位置、发布者、版本、适用范围、片段编号和定位
提问时 识别问题与条件 → 检索候选 → 选择实际送入模型的片段 → 生成 → 逐项核验 原始问题、候选排序、实际输入、原始输出、引用和核验结论

顺着第二条路径可以重放一次运行。反过来，从答案中的“可以入场”追到支撑它的条款，就是一条证据链。只有一个首页网址时，核验者还得自己猜测系统依据了哪一版、哪一句。可用的链条应当短到同伴可以当场走通：答案中的主张 → 引用的片段 → 原文位置与版本 → 该版本为何适用于本题。

三、怎样把原始资料变成可引用的片段

先定资料的边界。 为谁服务，收哪些来源，截至哪一天，哪些对象可以看见这些资料？课程可以使用公开、获授权或明确标注的模拟材料。把公开通知和内部工作记录混在一个目录时，应在选候选之前按使用者权限限定可检索范围。没有纳入资料库的事实，系统不能声称已经核实。

以能解释一个条款为单位切分。 一般规则和紧随其后的例外，尽量放在同一片段。若把表格中“周末”单独切成一行，却丢掉“仅限团体预约”的列表头，检索可能命中正确的字，却交回了错误的意思。切分长表时给每段补回列名、单位和上级标题；扫描件的数字、日期、否定词要对照原图核一次。相邻片段适当重叠可以保留上下文，但评价时要按原件和条款去重。

让来源随正文一起流动。 每个片段至少能回答“谁发布的、说的是谁、何时有效、原文在哪里”。发布日期只回答“何时发出”；生效日、活动日期和替代关系决定它何时适用。保留旧版有助于回答历史问题。处理现行问题时，要能识别被替代的具体条款，不能仅凭文件排在最后就把整份旧文件作废。

建库时容易丢掉的信息 问答时会出现的症状 回头怎样查
照片说明、列标题或单位 把试运行日期当成常规开放日期 打开原页，连标题和相邻行一起读
条款中的对象和例外 把团体预约规则说成人人适用 对照条款主语、条件和例外句
原始出处与转载关系 把同一通知的两次转载当作两份独立证据 沿署名和出处回到首次发布者
版本和生效范围 回答在上月正确，在用户问的日期已经错误 并排核对旧条款、新条款和变更范围

四、检索器为什么会“找到了相似的话，仍然没找到答案”

关键词检索擅长抓住活动全名、文件号、房间号等精确线索。BM25 属于词项匹配方法，会考虑词项在一段文字中的出现情况、在语料中的稀有程度以及段落长度。它可能漏掉“结束后还能进去吗”和“停止入场”这样的改写。下面的课堂基线只做透明的标签匹配，便于手算每一次得分。Robertson 与 Zaragoza，2009

向量检索把问题和候选片段编码成向量，再按相似程度排序。DPR 用两个编码器分别表示问题和段落。遇到近义表达时，这条路线可能找回关键词方法漏掉的片段；遇到同名活动、不同年份、一般规则和例外条款时，语义接近的段落也可能给出相反结论。对一个项目是否有帮助，要在该项目自己的问题上检查。Karpukhin 等，2020

例如，用户问“这周六还能领票吗”，检索时可以保留原问，同时把“这周六”换算为询问当日所指的具体日期，把活动名称加入查询。如果原对话里根本没有说明哪一场，先请用户补活动名。把臆测的活动名写进查询，得到再高的相似度也只能说明系统擅长回答另一个问题。

Top-k 表示最多保留前 k 个候选。取太少可能只拿到规则、漏掉例外；取更多可能同时带回几份无关通知。实际项目可先用词项和向量两种方法各取若干候选，按片段编号合并去重，再用问题与候选的配对相关性重新排序。最后在上下文预算内保留完整条款。调试时分别保存“检索排出的候选”和“模型最终看到的文本”，否则无法判断证据是没找到，还是找到了却在拼装时被截掉。

五、从证据写到结论

把“这是一段流畅的回答”换成一个具体动作：圈出日期、数量、对象、条件和行动建议，逐项问“哪一句支持它？”同一句里的两个事实可能要引用两段材料。段落结尾只放一个网址，往往看不出该网址究竟支持哪一半。带引用生成的研究也区分答案正确性和引用质量；在课堂上我们进一步逐句核对，以便找出第一个需要修改的地方。Gao 等，2023

当前证据 面向用户的写法 审核时要问
有直接条款，条件吻合 给简短结论，在事实之后标片段号和条款 原文是否支持对象、日期和例外？
已知一部分，另一部分欠缺 先回答有依据的部分，再点出缺的字段 有没有把“未提及”擅自改写为“禁止”或“免费”？
新通知明确替代旧条款 说明哪一条在何时被改动，用当前有效条款回答 替换是否只涉及某个时段、对象或服务？
两份同时适用的文件互相矛盾 并列原句和出处，指出冲突点，提出具体核实对象 有没有依据解决冲突？哪一方能作最终确认？
当前片段均未交代 说明本次检索的范围和缺口，给出下一步查询方向 可否再检索一次？是否把“这次没找到”误说成“机构没有规定”？

对于派生数字，应写出参与计算的值、单位、去重假设和所用公式。对于外部材料，把其内容当作待核实的事实陈述；即使片段中出现要求改变回答格式或执行额外操作的句子，也继续依据课程给定的任务和权限处理。证据说明事实，应用自身的操作授权由另一套规则决定。

算一次，再定位错误

在 Q1、Q2、Q3、Q4、Q6 中，五题分别要求找到 1、1、1、2、2 个片段。以“题目与必需片段的配对”为单位，七对命中六对，微平均证据召回率为 6/7，约 85.7%。若要求一道题的必需证据全部进入前两条，则完整覆盖 4/5 题，80%。Q5 的必需证据集合为空，单列检查答复有没有把“资料未说明”写成“没有直播”，不计入这两个分母。以上数字只描述本次小语料的检索行为。

保留 Q6 首轮日志，再把地点和入场凭证拆成两个查询。使用原标签、原排序和相同的每次返回上限，分别记下两次结果、合并去重后的片段以及支持两项主张的原句。比较时一并报告检索次数与最后交给答题人的片段数。为检查改法能否迁移，可由另一组拟一道未参与调整的新问题，运行前先封存其参考依据。

在 R 里复现这次检索

下面的代码可以整段复制到 R 控制台运行，只用基础 R。文档标签由教师预先标定，程序在每道原问中逐个查找这些词。这一步让大家能检查排序、并列和截断的影响；换成真实的自由提问，还要单独检验系统能否识别相同的意图和条件。代码先运行检索，再使用参考证据评分。输出可直接对照上面的核验卡。

document_tags <- list(
  D1 = c("地点", "费用", "预约"),
  D2 = c("地点", "改址"),
  D3 = c("寄存", "东门"),
  D4 = c("寄存", "西门"),
  D5 = c("预约", "入场", "证件")
)
questions <- c(
  Q1 = "改址后的活动地点在哪里？",
  Q2 = "参加这场展览的费用是多少？",
  Q3 = "开幕日入场要带哪些证件或凭证？",
  Q4 = "开幕日去哪里寄存行李？",
  Q5 = "开幕日有直播吗，网址是什么？",
  Q6 = "改址后的活动地点在哪里？只有预约确认码就能入场吗？"
)

retrieve <- function(question, k = 2L) {
  vocabulary <- unique(unlist(document_tags, use.names = FALSE))
  matched <- vapply(vocabulary, function(tag) grepl(tag, question, fixed = TRUE), logical(1))
  query_terms <- vocabulary[matched]
  scores <- vapply(document_tags, function(doc) length(intersect(query_terms, doc)), integer(1))
  ranking <- order(-scores, names(scores))
  positive <- ranking[scores[ranking] > 0]
  scores[head(positive, k)]
}
ranked <- lapply(questions, retrieve)
print(ranked)                         # 显示每题返回的片段编号、顺序与得分
returned <- lapply(ranked, names)     # 评分只用片段编号

# 参考证据仅供检索后的评分使用
gold <- list(Q1 = "D2", Q2 = "D1", Q3 = "D5", Q4 = c("D3", "D4"),
             Q5 = character(0), Q6 = c("D2", "D5"))
recover <- function(found, required) length(intersect(found, required))
hits <- mapply(recover, returned, gold)
needed <- lengths(gold)
with_evidence <- needed > 0
cat("找回的必需片段数／所需片段总数：",
    sum(hits[with_evidence]), "/", sum(needed[with_evidence]), "\n")
cat("取全证据的题数／有参考证据的题数：",
    sum(hits[with_evidence] == needed[with_evidence]), "/", sum(with_evidence), "\n")

给生成模型的材料如何准备？ 运行 returned[["Q6"]]，只把返回编号对应的原文、日期、版本和定位与 Q6 原问送入生成模型；隐藏本讲义中的参考依据和其他片段。保存模型原答。然后只对 Q6 将上限改为 3，再次核查：retrieve(questions[["Q6"]], k = 3L) 会取回 D1、D2、D5。此时可以核查两条独立主张。人工参考答复为：“请到二层声音实验室〔D2§1〕。仅有预约确认码还不够，入场须同时出示本人有效学生证〔D5§3〕。”把生成模型的真实答复与这两处原句核对，特别留意“同时”是否保留。

七、怎样定位错误发生在哪一步

对同一个错答做两次回放。第一次保留原始检索结果，记下系统真正看到了什么。第二次仅为诊断，人工换入经过核验、足够回答问题的片段，保持问题与生成提示相同。第二次若答对，优先检查检索、切分和上下文拼装。若仍然答错，再看生成时是否误读了范围、版本或数字。请把这次人工干预单独标记，课堂演示中补进的金标准片段不能混入系统实测成绩。

回放时最先发现的断点 查哪个环节 可尝试的一处改动
原始目录里没有必要的条款 资料覆盖 查明有权使用的首发来源，将原件和版本加入下一版材料
原件有条款，索引片段丢了例外句 提取与切分 把小标题、对象、主规则和例外放回同一段，重建该文档索引
索引片段完整，前 k 项中没有它 检索 检查问法是否缺名称、日期或同义词，测试一种查询改写
候选中有正确片段，最终输入里没有 上下文拼装 检查去重、排序和截断，保留主规则及其必要补充条款
最终输入齐全，答案仍扩大了适用人群 生成 要求逐项输出对象、条件、片段号，再用原题复测
结论看似正确，引用却指向别处 引用与核验 把结论拆为独立主张，逐个跳转到条款并比对原句

复测先固定资料快照、问题、生成提示和可见片段上限，一次改一个环节。若两次使用了不同平台、不同知识库和不同提示，只能说两个完整方案在这组题上的表现不同。开发时看过答案的题可用于诊断；另留至少一道未参与调参的新问法，最后检查改动能否迁移。

八、怎样评价带来源的回答

检索表回答“要求看到的材料，到底找回了几段”。若一道题需要两段证据，得到其中一段就算命中，但只找回了一半的必需证据。课堂中对有参考证据的题可算 Recall@k，即前 k 项找回的必需片段数除以这道题全部必需片段数。若有多种同样有效的来源，评测前应约定哪些来源可以互相替代。无答案题的参考证据集合为空，单列判断其回应是否适当。

回答表进一步分开三项。内容看事实及适用条件是否正确；引用看每个引用是否真实存在且支撑相连的主张；边界看遇到资料不足或冲突时有没有如实说明。模型可能碰巧答对并引用了无关段落，在内容栏得分，并不能弥补引用栏的错误。

以下是一个独立的计分示意。某答复有三项需要依据的主张：开放时间、预约对象、票价。其中开放时间引用正确，预约对象附有引用但引错条款，票价没有引用。三项中只有一项得到充分支持，主张支持覆盖为 1/3；给出的两处引用中只有一处支持相连的主张，引用支持比例为 1/2。两个分母衡量的对象不同。对资料不足题，另记“正确说明缺口的题数／资料不足题数”，并检查是否把本来可答的题也一概回绝。小样本报告保留题号、分子和分母，便于同伴逐题复核。

九、实操一 · 提交一条可以回放的证据链

沿用个人项目，选择一个范围明确的问题，例如“这份报道所说的人数对应哪一天”“这篇论文的结论适用于哪个样本”“这场活动的预约规则适用于哪些观众”。先写出准备交给哪位用户、什么算答对，再整理有权使用的资料。开发阶段可以使用课堂题熟悉流程，最终展示请换成自己项目中的资料和问题。

  • 传媒核查。 一份新闻稿写“报名 300 人”，现场报道写“到场 180 人”。将日期、统计对象、原文位置分别存入两个片段。若用户问实际到场人数，引用现场记录，并保留“报名”和“到场”的口径。两个数字可以同时成立。
  • 文献辅助阅读。 用户问“这项研究能推广到所有观众吗”。一并检索方法中的样本范围和讨论中的限制段落。若只找到摘要里的总体结论，记录缺少哪段方法依据，让使用者能跟进原文。
  • 公共文化服务。 同一场馆的日常开放、临时闭馆和已预约观众的改签办法可能由三份通知说明。提问若涉及“明天还能去吗”，先核实具体日期、场馆和票种，再检查临时措施覆盖了哪些人。

若使用问答平台，随记录写明平台、模型标识、运行日期和实际可见的设置。若同学扮演答题者，请标作“人工演练”。两种做法都应保留原始答复，这样后来的人才能区分系统说了什么、同学又修了什么。

同伴互查时可以先遮住参考答案，只凭运行记录回答三个问题：系统见过哪一句？这句足以支持答复中的哪几个字？删除它以后，哪一项结论必须改写？能答出这三个问题，一条证据链才真正交到了下一位读者手里。
